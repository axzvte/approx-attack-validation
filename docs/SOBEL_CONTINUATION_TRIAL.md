# Sobel：连续区间细化与局部硬件搜索试点

本试点验证两项修改能否减少确定硬件的时间：已有好结构的局部修改，以及单次进程内持续细化区间。选择 Sobel 是因为上一轮其训练约43分58秒、筛选约25分22秒，确定硬件合计约69分20秒；10张新图测试约2分59秒。没有针对 Sobel 改 ROI、整体PSNR门槛、节点数量上限或翻转位规则。

代码及测试仅完成编写和静态审查；编写方没有执行编译、测试、语法检查或实验。实际耗时和效果由用户运行后确认，不能预先承诺加速比或与旧搜索得到相同解。

## 与上一轮 balanced 的区别

| 环节 | balanced（保留） | continuation（本次试点） |
|---|---|---|
| 图1–2 | 充分预算的独立候选发现 | 相同 |
| 图3–10 | 先独立发现，再校准先前候选 | 先校准先前候选，再用当前图合法配置引导局部发现 |
| 后续发现起点 | 从正常基准开始 | 当前图校准得到的好配置，并保留基准起点探索 |
| 结构修改 | 自由节点/信号/位组合 | 局部分支以原始起点为锚，默认最多1处结构编辑；全局分支仍可发现新组合 |
| 区间投入 | 低/中/高档分别启动程序 | 一个程序内共享搜索状态、参考、追踪和缓存 |
| 后续细化 | 独立档位分别从训练起点开始 | 保留当前候选继续细化，始终保留最好合法解 |

训练后仍按原规则去重并取最多12套候选，在11–20筛选H*，冻结节点/信号/翻转位及训练起点后，再对31–40单独调区间。分组、原近似单元、signed12输入/signed13输出、0–11非符号位、原ROI及数值资格不变。无背景数值硬门槛，无消融；图片仅选中输出、ROI对比、背景对比三张。

## 局部搜索的边界

“一处结构编辑”是：增加一个节点、删除一个节点，或者改变某个节点的监控信号/翻转位。区间L/U改变不算结构编辑。距离始终相对于传入的原始结构起点计算，不能通过连续小步无限偏离起点。默认参数 `--structure-radius 1`。

图3–10仍使用原来的64个条件分析预算。其中默认16个留给从正常基准开始的探索，其余用于局部搜索；这是同一个预算中的分配，不是64+16。参数 `--global-exploration-fraction 0.25`控制分配。没有可用先前结构，或传入起点在当前图全部范围非法时，回退到相同总预算的基准起点探索。

局部搜索不会仅凭一个节点独立不敏感就永久删除它。即使某个节点不能再改变监控信号或翻转位，仍可在结构半径允许的配置下调整其区间；联合上下文中的下游触发和最终质量照常重算。结构种子模式保留配置中的零触发安装节点，避免导出清理悄悄改变局部距离；最终固定硬件阶段也始终保留所有安装节点。

当前图的局部起点来自当前训练图上已有H的真实合法执行结果，不直接把前图的区间当成当前图已验证配置。数值未达标但合法的起点也可以引导后续搜索。训练图证据可以进入训练池，筛选/测试新产生的区间不能回写训练起点库。

## 单次进程内的区间细化

`--workflow continuation`对一个“图片+固定H”只调用一次原生区间程序，带 `--continuous`。原生求解器在同一调用中保留当前beam、合法/达标最好解、条件分析缓存、精确参考和单份配置追踪；完整配置变化后重新计算相应条件响应，不复用不匹配的追踪。

只有至少两个完整细化轮次结束后，且已有数值达标结果、最好ROI MSE的相对改善低于 `--adaptive-min-gain 0.001`，才可按停滞结束。这与旧冷启动分档比较ROI PSNR下降的停止指标不同；它直接跟随当前最大化ROI MSE的目标。最大轮次由原 refinement/restarts 参数决定；context上限仍128，完整评价上限仍256（Sobel使用条件像素评分）。预算不足可能在两个完整轮次前结束，报告为预算限制，不能说已收敛。

这项策略不再进行三个独立的冷启动。`interval_attempts.csv`中的一行对应一次完整原生调用，细化轮数查看 completed_sweeps，停止原因查看 stopped_for_convergence及原有预算字段。已得到过的最好结果仍通过原应用完整重放核验。

`continuation`使用自己的原生连续策略，要求 `--adaptive-intervals auto`（默认）；不要再用on/off切换旧分档方式。原 `balanced`和 `reference`模式继续可用。锐化原生连续实现尚未接入，这个新模式不会静默套用到锐化入口；本轮只要求 Sobel 实测。

## 用户运行命令

在 WSL 仓库根目录执行。构建与检查通过后再启动实验，避免测试失败仍继续运行：

```bash
git switch feature/sharpen-bitflip
git pull --ff-only origin feature/sharpen-bitflip
cmake -S . -B build-bitflip -DCMAKE_BUILD_TYPE=Release
cmake --build build-bitflip -j4
ctest --test-dir build-bitflip --output-on-failure && \
python3 scripts/run_circuit_bitflip_hardware.py \
  data results/bitflip/sobel_continuation_20261026 \
  --applications sobel --workflow continuation \
  --screen-workers 4 --skip-build
```

输出目录必须不存在。本命令重新做1–10训练，不传 `--training-report`，才能观察训练和硬件确定时间的变化。首次测量也不传 `--resume-from`，避免把缓存收益混入搜索策略比较。需要补跑中断任务时仍可使用只读resume，命中数量会报告，但那次用时应单独解释。

旧策略的历史对照目录为 `results/bitflip/circuit_workflow_balanced_20261025/sobel/`。它来自先前的电脑负载与运行环境，不能当成严格单因素加速结论；如需同一版本重测，可在新输出目录运行相同命令，仅把workflow改为balanced。该试点同时改变局部发现与区间细化，整轮差异不能分别归因给其中一项。

沿用31–40便于比较当前开发效果；它们已经被查看过，本轮属于同批图片的开发对照。视觉结论仍须核对ROI和背景图片。
